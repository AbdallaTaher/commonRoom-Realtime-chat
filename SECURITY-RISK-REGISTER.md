# Security Risk Register

Severity is scored as likelihood (1–5) × impact (1–5). Scores 1–4 are low, 5–9 medium, and 10–25 high. This is a project-level review, not a penetration test.

| Risk                                                                      | Likelihood | Impact |      Score | Mitigation and remaining work                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------- | ---------: | -----: | ---------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A signed-in user sends messages at an abusive rate                        |          3 |      3 | 9 (medium) | A database trigger limits each account to 30 messages per minute, including direct RPC calls. Supabase Auth has its own configurable limits for login, signup, and password reset requests; review those in the Supabase dashboard before public deployment.                                                                                                               |
| A user reads another member’s private conversations or changes their data |          2 |      5 |  10 (high) | RLS is enabled on application tables. Conversation RPCs check membership and group ownership, profile updates are row-scoped, and service-role credentials are not used by the browser. Recheck policies whenever a table or RPC is added.                                                                                                                                 |
| Workspace realtime leaks private conversation events                      |          2 |      4 | 8 (medium) | Conversation events require membership; workspace-wide subscriptions are restricted to presence events. Presence itself is visible to authenticated members by design.                                                                                                                                                                                                     |
| A malicious avatar upload is stored or displayed                          |          2 |      3 | 6 (medium) | Uploads are capped at 2 MB, checked against PNG/JPEG/WebP file signatures and MIME, and stored in Supabase Storage. Avatars are intentionally public. Antivirus scanning is not configured for this portfolio project.                                                                                                                                                     |
| Cross-site request forgery triggers a signed-in mutation                  |          2 |      4 | 8 (medium) | Mutations use Next.js Server Actions, which enforce request origin checks, and Supabase RLS/RPC authorization remains the data boundary. Keep deployment host/origin configuration restrictive; there are no custom mutation Route Handlers.                                                                                                                               |
| Session cookies or credentials are exposed                                |          2 |      5 |  10 (high) | Supabase SSR manages session cookies; production must use HTTPS. Keep `.env.local` uncommitted and never place the service-role key in `NEXT_PUBLIC_*` variables. Review Supabase Auth’s session and password settings before public deployment.                                                                                                                           |
| User-generated text causes script execution                               |          2 |      4 | 8 (medium) | Chat and profile text render as React text, not injected HTML. Do not introduce `dangerouslySetInnerHTML` for user content without a sanitizer and a separate review.                                                                                                                                                                                                      |
| Vulnerable CSS selector parser in the development/build dependency tree   |          1 |      3 |    3 (low) | `npm audit` reports a moderate denial-of-service advisory in `postcss-selector-parser` pulled in by Tailwind CSS 3. The reported attack requires parsing attacker-controlled CSS, which this app does not do at runtime. CI currently fails high-severity advisories; upgrade Tailwind or adopt a verified compatible parser override before raising the gate to moderate. |
